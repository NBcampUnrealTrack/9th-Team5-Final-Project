# 인벤토리와 퀵슬롯

플레이어의 아이템은 하나의 `ASInventoryComponent`에서 관리한다. 화면에 표시하는 위치만 나눈다.

- 슬롯 0–9: 기존 퀵슬롯. 키 매핑은 기존과 동일하게 1–9, 0이다.
- 슬롯 10–25: 기본 보관함 16칸. 가방을 장착하면 이 구역의 뒤에 슬롯이 추가된다.
- 슬롯 -2: 무기 장착 위치.
- 슬롯 -3: 가방 장착 위치. 장착 아이템은 보관 공간을 사용하지 않는다.

`I` 또는 PlayerController의 `ToggleInventory`로 전체 창을 열고 닫는다. Escape도 창을 닫는다. 창이 열려 있는 동안 우측 아래 퀵슬롯 HUD는 숨기고, 같은 슬롯을 창의 하단에 표시한다. 창의 상단에는 무기/가방 장착칸, 가운데에는 8열 보관함이 있다. 확장된 보관함은 스크롤할 수 있고 작은 화면에서는 창을 축소한다. `무기 제작` 버튼은 기존 레시피 제작 창으로 연결한다.

## 조작

- 클릭: 아이템 사용 또는 장착. 장착 중인 가방을 클릭하면 해제를 요청한다.
- 드래그: 퀵슬롯/보관함 사이 이동, 같은 아이템 스택 합치기.
- 가방을 Bag 칸으로 드래그: 장착 또는 교체.
- 장착 가방을 빈 일반 슬롯으로 드래그: 해제. 해제 후에도 존재하는 슬롯이어야 한다.
- 일반 슬롯의 아이템을 창 밖으로 드래그: 해당 스택 버리기.
- Ctrl+우클릭: 일반 슬롯에서 1개 버리기.

장착 가방은 창 밖으로 직접 버릴 수 없다. 먼저 해제한 뒤 버린다. 가방을 해제하거나 작은 가방으로 교체할 때 사라지는 슬롯에 아이템이 있으면 남은 빈칸으로 재배치한다. 이전 가방을 보관할 칸까지 계산해 공간이 부족하면 전체 변경을 거부한다. 아이템을 자동으로 삭제하거나 바닥에 버리지 않는다.

## 가방 추가

가방마다 별도의 `ASItemDefinition` 데이터 에셋을 만든다. `ItemType = Bag`, `MaxStackSize = 1`, `Rarity`, **Item → Bag → Bag Additional Slots**를 지정한다. 아이콘과 이름은 기존 아이템과 같은 방식으로 설정하고, 시작 아이템이나 전리품 데이터에 등록하면 된다. 가방별로 PlayerController 목록에 추가할 필요는 없다.

용량은 **장착한 가방 아이템 자체의 Bag Additional Slots 값**으로 결정한다. 등급은 아이템 품질/표시에 사용하며, 용량을 등급에 맞춰 자동 계산하지 않는다. 아래 값은 가방 아이템을 만들 때 지정할 수 있는 예시다. 같은 등급의 가방도 서로 다른 용량을 가질 수 있다.

| 등급 | 추가 보관칸 | 보관함 전체 | 퀵슬롯 포함 |
|---|---:|---:|---:|
| 가방 없음 | 0 | 16 | 26 |
| Uncommon | 8 | 24 | 34 |
| Rare | 16 | 32 | 42 |
| Epic | 24 | 40 | 50 |
| Legendary | 32 | 48 | 58 |

예를 들어 `DA_Bag_Small`은 추가 8칸, `DA_Bag_Large`는 추가 20칸으로 만든다. 두 가방을 가지고 있기만 하면 총 26칸이고, 작은 가방을 장착하면 34칸, 큰 가방을 장착하면 46칸이 된다. 가방을 해제하면 기본 26칸으로 돌아간다.

서버가 장착 상태와 슬롯 이동을 검증하며 기존 아이템 인스턴스 복제로 클라이언트에 전달한다. UI는 인벤토리 변경 알림으로 슬롯 수를 갱신한다. 가방 용량은 아이템 에셋에서 플레이 시작 전에 조정한다. 전리품 컨테이너의 `MaxSlots` 설정(0은 무제한)은 기존 의미를 유지한다.

## 구현 위치

- `ASInventoryBags.cpp`: 플레이어 용량 계산, 가방 장착과 안전한 축소.
- `ASItemDefinition.BagAdditionalSlots`: 가방 아이템별 추가 보관칸.
- `ASInventoryPanelWidget`: 전체 인벤토리 창. 기존 슬롯 위젯과 드래그 동작을 재사용한다.
- `ASInventoryWindowInteraction.cpp`: 로컬 창 열기/닫기와 입력 포커스.
- `ASInventoryMutationPlan` / `ASInventoryTransactions.cpp`: 초기 지급과 제작에서도 현재 가방 용량을 사용한다.
